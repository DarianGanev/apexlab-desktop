# ApexLab v0.2 Capture Evidence Implementation Plan

> **For Codex:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` task by task. Use `superpowers:test-driven-development` for production behavior, isolated worktrees for every branch, and a frozen-diff independent review before every push or merge.

**Goal:** Deliver the smallest trustworthy F1 25 v3 capture-evidence vertical: strict header and packet-envelope validation, bounded loopback UDP ingestion, early private real-traffic cross-check, a bounded opaque evidence file, deterministic replay, and actionable desktop diagnostics.

**Architecture:** Protocol-neutral envelopes, adapter contracts, and results live in `Telemetry.Abstractions`. `Protocols.F125` implements that contract without referencing Application. Application owns workflows, state, counter aggregation, sender policy, and infrastructure ports. Telemetry owns sockets and bounded admission. Persistence owns the minimal v0.2 evidence file and replay source. WPF and `tools/ApexLab.Replay` are composition roots over the same Application ingestion workflow.

**Technology:** C# 14, .NET 10 LTS, WPF, `System.Buffers.Binary`, `System.Net.Sockets`, `System.Threading.Channels`, SHA-256, MSTest, PowerShell, GitHub Actions.

**Release target:** `v0.2.0`

## Deliberate v0.2 boundary

Version 0.2 proves that ApexLab can recognize and retain real base-F1-25 evidence honestly. It does **not** implement production raw chunks, compression, crash recovery, storage quotas, SQLite capture indexes, full packet bodies, or session reconstruction. Those remain v0.4 work.

The v0.2 evidence store is one bounded, uncompressed, append-only file plus a final integrity manifest. Default hard limits are 15 minutes, 512 MiB, and 1 GiB required free space. Reaching any limit stops capture with a specific result. These hard limits prevent an indefinitely armed validation capture from filling the disk; configurable quota management remains v0.4.

## Non-negotiable invariants

- Base F1 25 UDP mode only: packet format `2025`, game year `25`, base v3 attachment.
- The exact base attachment filename, byte size, and SHA-256 are recorded before descriptor implementation. The ignored vendor copy is never committed.
- A bounds-checked reader performs every little-endian read; parser code uses no marshal/unsafe layout.
- An immutable descriptor table is the compatibility authority for packet ID, packet version, exact datagram length, and privacy disposition.
- Unknown IDs, wrong versions, wrong lengths, malformed headers, Season Pack traffic, and
  identity-bearing packets never enter evidence. Participants and Lobby Info are explicitly
  excluded, and every future descriptor requires a field-level privacy audit.
- The receiver binds `127.0.0.1:20777` by default. v0.2 has no all-interface/LAN mode.
- Memory is bounded. A `maximumDatagramBytes + 1` sentinel receive buffer or Windows truncation flag distinguishes exact-boundary input from oversized input.
- The bounded channel uses `BoundedChannelFullMode.Wait` with `TryWrite`; a failed admission is observable and counted.
- Accepted receive bytes are copied once to exact-length owned memory before the receive buffer is reused.
- One component owns each counter and completion transition.
- Evidence is described as **complete and integrity-verified**, never authenticated or “trusted” merely because SHA-256 matches.
- Replay preserves recorded sequence gaps and uses deterministic awaited admission, not the live source’s nonblocking drop policy.
- Real captures remain only under the configured local ApexLab capture root. No real, cropped, or pseudonymized packet becomes a fixture.
- Committed fixtures are independently authored, deterministic, and document their generation and SHA-256.

## Counter ledger

Names may be refined in code, but ownership and equations may not.

### UDP source-owned

- `DatagramsObserved`
- `SourceEnqueued`
- `SourceDroppedFull`
- `SourceRejectedOversized`
- `SocketErrors` (operation failures, not datagrams)

After a completed receive loop:

```text
DatagramsObserved = SourceEnqueued + SourceDroppedFull + SourceRejectedOversized
```

The source records sender metadata but does not decide whether a sender is expected.

### Application classifier-owned

- `SourceDequeued`
- `Compatible`
- `MalformedHeader`
- `UnsupportedFormat`
- `UnsupportedYear`
- `UnknownPacketId`
- `UnsupportedPacketVersion`
- `InvalidPacketLength`
- `ExcludedPrivacyPacket`
- `UnexpectedSender`
- `ClassifierAbandonedOnTermination`

After a clean drain:

```text
SourceDequeued =
  Compatible + MalformedHeader + UnsupportedFormat + UnsupportedYear +
  UnknownPacketId + UnsupportedPacketVersion + InvalidPacketLength +
  ExcludedPrivacyPacket + UnexpectedSender

SourceEnqueued = SourceDequeued
```

After an interrupted drain:

```text
SourceEnqueued = SourceDequeued + ClassifierAbandonedOnTermination
```

### Evidence-store-owned

- `SinkWritten`
- `SinkWriteFailed`
- `SinkPending`
- `SinkPendingDeferredCleanup`
- `FinalizedRecords`
- `StagedRecords`

Classification and transition to `SinkPending` occur atomically in the workflow ledger before the
asynchronous store call begins. On normal completion, the workflow atomically replaces that pending
count with either written or failed. If bounded stop expires, each unresolved pending write is
atomically transferred to `SinkPendingDeferredCleanup`.

```text
During an active or cleanly stopping capture:
Compatible = SinkWritten + SinkWriteFailed + SinkPending

After a bounded stop returns Interrupted:
Compatible =
  SinkWritten + SinkWriteFailed + SinkPendingDeferredCleanup

At every consistent snapshot:
SinkWritten = FinalizedRecords + StagedRecords
```

`FinalizedRecords` remains zero until the completion manifest is committed, at which point all
successfully staged records move atomically from `StagedRecords` to `FinalizedRecords`. Deferred
writes eventually move from pending-deferred to written or failed. Cumulative counters become
immutable only when `DeferredCleanupCompletion` finishes; earlier interrupted snapshots are
explicitly provisional.

The UI uses “received,” “compatible,” “pending,” “written,” and “finalized” literally. It never
labels compatible, pending, or written records as durable final evidence before manifest
finalization.

## Capture state transitions

| Current | Event | Next | Rule |
|---|---|---|---|
| `Idle` or `Stopped` | Arm | `Binding` | Creates a new capture identity; concurrent Arm callers share one task. |
| `Binding` | Bind success | `WaitingForTraffic` | Source and consumer ownership are published together. |
| `Binding` | recoverable bind/configuration failure | `Stopped` | Records the actionable failure; corrected settings may be armed again. |
| `Binding` | unrecoverable failure | `Faulted` | No producer ownership is leaked. |
| `WaitingForTraffic` | compatible packet | `ReceivingCompatibleTraffic` | Status snapshot only; ingest remains off UI thread. |
| `WaitingForTraffic` or `ReceivingCompatibleTraffic` | incompatible packet | `IncompatibleTraffic` | Later compatible traffic may return to `ReceivingCompatibleTraffic`. |
| `IncompatibleTraffic` | compatible packet | `ReceivingCompatibleTraffic` | Compatibility recovery is visible without restarting capture. |
| Any armed nonterminal state | Stop | `Stopping` | Concurrent Stop callers share one bounded stop task. |
| `Stopping` | clean drain/finalize | `Stopped` | Another Arm starts a new identity. |
| `Stopping` | timeout/ownership unresolved | `Interrupted` | Lease/ownership is retained until deferred cleanup resolves. |
| `Interrupted` | deferred cleanup succeeds | `Stopped` | Counters become immutable and retry is allowed. |
| `Interrupted` | deferred cleanup fails | `Faulted` | Final cleanup failures remain observable; retry requires explicit reset after ownership resolution. |
| `Faulted` with resolved ownership | Reset | `Stopped` | Clears only the active failure presentation, not diagnostic history. |
| Any non-disposed state | unrecoverable failure | `Faulted` | Cleanup still runs and aggregates failures. |
| Any state | Dispose requested | current stop/cleanup state | Arm throws immediately, but public state does not hide unresolved ownership. |
| Any resolved state with Dispose requested | cleanup completes | `Disposed` | `Disposed` is published only after ownership resolves; terminal failure remains available. |

**Primitive reader behavior**

- Read signed/unsigned 8/16/32/64-bit values and IEEE-754 `float`.
- Expose position/remaining.
- Insufficient input returns `false`, leaves position unchanged, and never publishes partial output.
- Use `BinaryPrimitives`; allocate nothing based on input size.
- Test every width, unaligned reads, every short boundary, failed-read recovery, float bit patterns, and deterministic seeded random input.

**Header behavior**

Decode exactly 29 bytes in published order:

1. packet format (`ushort`)
2. game year (`byte`)
3. game major version (`byte`)
4. game minor version (`byte`)
5. packet version (`byte`)
6. packet ID (`byte`)
7. session UID (`ulong`)
8. session time (`float`)
9. frame identifier (`uint`)
10. overall frame identifier (`uint`)
11. player car index (`byte`)
12. secondary player car index (`byte`)

Structural decoding accepts trailing body bytes and preserves an unknown packet ID. The adapter
then requires an exact descriptor match for ID, version, and total datagram length. Every descriptor
is field-audited for identity-bearing content. Participants and Lobby Info are represented with an
excluded privacy disposition, and any future identity-bearing family defaults to excluded.
Unknown/unsupported data returns a typed classification and no decoded compatible result.

**Tests**

- Every prefix length 0-28.
- Wrong endianness, format, year, ID, version, and exact length.
- Synthetic Participants and Lobby Info datagrams prove identity-bearing families never become
  compatible evidence, even when ID/version/length are otherwise valid.
- Every byte-valued ID cannot cause array indexing failure.
- Fixed-seed random corpus records seed and failing bytes.
- Fixture metadata states it was independently authored and contains no real capture bytes.

**Normative format first**

No writer code begins until `raw-evidence-v1.md` is reviewed. It specifies:

- every magic value, field order, byte width, signedness, little-endian rule, and fixed encoding;
- uncompressed framing and maximum record/file sizes;
- capture identity encoding;
- absolute monotonic timestamp ticks plus recorded `Stopwatch.Frequency`;
- UTC ticks, capture sequence, sender metadata, payload length, and exact payload bytes per record;
- nondecreasing arrival ticks and strictly increasing sequence, with sequence gaps allowed;
- empty-file first/last sequence sentinels;
- footer placement and counts;
- SHA-256 domain as the entire finalized evidence file including footer;
- a canonical bounded UTF-8 JSON manifest that is the completion marker;
- streamed length/decompression-independent bounds (v1 has no compression);
- finalization ordering: write `.partial`, footer, `FileStream.Flush(flushToDisk: true)`, hash, write and flush manifest partial, rename data, rename manifest last;
- honest limitation that directory-entry durability and crash recovery are deferred to v0.4.

A final file is complete and integrity-verified only when its final manifest exists, schema/limits match, and SHA-256 verifies. SHA-256 does not authenticate a malicious file.

**Storage rules**

- Use `ApplicationPaths.RawCapturesDirectory`; no parallel `/raw` convention.
- Generate paths from capture IDs; reject caller-controlled absolute/relative paths.
- Reject reparse points before opening any generated path.
- Enforce 15 minutes, 512 MiB, and 1 GiB free-space floor by default.
- `.gitignore` adds `*.apxraw`, `*.apxraw.json`, and `/private-validation/`.
- `Verify.ps1` fails if raw evidence/private-validation content is tracked.
- No `.apxraw` or manifest fixture is committed. Raw-format tests generate independently authored
  records in memory or under test-owned temporary directories and delete them after verification.
  Small synthetic packet-byte fixtures may be committed only with the data-policy metadata.

**Replay rules**

- Immediate mode uses deterministic awaited admission and therefore has no scheduler-dependent live-channel drops.
- Recorded mode injects `TimeProvider` and uses `Task.Delay(delay, timeProvider, token)`; tests use virtual time.
- Speed is integer permille in `[100, 100000]` (0.1x-100x).
- Target elapsed `TimeSpan` ticks are calculated with checked `Int128` arithmetic and half-up rounding:

```text
targetTicks =
  roundHalfUp((arrivalDelta * TimeSpan.TicksPerSecond * 1000) /
              (recordedStopwatchFrequency * speedPermille))
```

- Equal arrival ticks require no delay; regressed ticks are invalid; very large delays remain cancellable; original sequence gaps are preserved.
- Replay invokes the same Application classifier/coordinator and produces the same classification ledger.
