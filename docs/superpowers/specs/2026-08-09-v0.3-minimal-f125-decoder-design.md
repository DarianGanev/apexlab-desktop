# v0.3 Minimal F1 25 Decoder Design

**Status:** Approved under the owner's standing instruction to make routine engineering decisions
without pausing for approval.

**Issue:** [#25](https://github.com/DarianGanev/apexlab-desktop/issues/25)

## Objective

Decode exactly the five packet families and fields frozen by
`apexlab-bahrain-tt-slice-v1` into typed, unit-bearing values without weakening the existing v0.2
capture boundary. Truncated, wrong-format, wrong-version, wrong-length, invalid-index, and malformed
selected values must fail closed without exceptions or partially published packet values.

The decoder is a wire-format component. It does not decide whether two laps are comparable, infer
validity, build the canonical cache, align laps, or make a coaching claim.

## Considered approaches

### 1. One allocation-heavy packet union

A single `Decode` method could return an interface implemented by five reference-type packet
records. Dispatch would be convenient, but a replay would allocate one object per selected UDP
packet. That creates unnecessary garbage-collector pressure in the future canonical replay path and
makes wrong-family casts a runtime concern.

### 2. Runtime JSON-driven field decoding

The committed contract could be loaded at runtime and interpreted as a field map. This would reduce
duplicated constants, but it would move protocol mistakes from compile time to runtime, require a
generic value bag, make units weaker, and couple packaged software to a repository governance
artifact. The JSON contract is a test oracle and review boundary, not production configuration.

### 3. Typed family decoders with a shared checked gate

Each selected family gets one typed, allocation-free value record and one public decode method. A
shared gate reuses the existing header/descriptor inspection, requires the expected packet family,
and validates the player-array index before any member offset is calculated. Small internal checked
field readers handle absolute packed offsets. This is selected because it keeps call sites explicit,
values strongly typed, failures observable, and the hot path allocation-free.

## Public API

The production namespace is `ApexLab.Protocols.F125.Decoding`.

`F125BahrainPacketDecoder` exposes:

- `DecodeMotion(ReadOnlySpan<byte>)`;
- `DecodeSession(ReadOnlySpan<byte>)`;
- `DecodeLapData(ReadOnlySpan<byte>)`;
- `DecodeEvent(ReadOnlySpan<byte>)`;
- `DecodeCarTelemetry(ReadOnlySpan<byte>)`.

Each method returns `F125DecodeResult<TPacket>`, where `TPacket` is a readonly value record. The
result has exactly one disposition:

- `Decoded`: a typed value and validated header are present;
- `Ignored`: a structurally valid item is deliberately outside the frozen sub-selection, currently
  an Event code other than `SSTA`, `SEND`, or `FLBK`;
- `Rejected`: the input violated a structural, compatibility, bounds, or field-domain invariant.

An ignored packet is not evidence and is not a decoder failure. A rejected packet never exposes a
typed value. The result may retain already validated header metadata for local diagnostics, but
never retains the datagram or a span into it.

The decoder publishes the immutable identity `f125-v3-minimal-decoder-v1`. Contract tests bind the
production constant to the frozen JSON identifier.

## Failure taxonomy and ordering

`F125DecodeReason` is stable, non-textual, and safe for aggregate local diagnostics:

1. `MalformedHeader`;
2. `UnsupportedFormat`;
3. `UnsupportedYear`;
4. `UnknownPacketId`;
5. `UnexpectedPacketFamily`;
6. `UnsupportedPacketVersion`;
7. `InvalidPacketLength`;
8. `PrivacyExcludedPacket`;
9. `InvalidPlayerCarIndex`;
10. `MalformedSelectedField`;
11. `EventCodeOutsideSlice` for the sole ignored disposition.

The existing `F125TelemetryProtocolAdapter.Inspect` remains authoritative for reasons 1–4 and 6–8.
The family decoder checks the expected packet ID after successful inspection, then requires
`m_playerCarIndex` in `[0, 21]` before calculating a player-array position. Structural failure order
is deterministic and tested.

`m_secondaryPlayerCarIndex`, Bahrain/Time Trial context, spectating, network state, assists, setup,
conditions, and recovery policy are decoded or preserved for later audit. They are not parser
failures. Issue #27 owns the provisional manual context match and abstention policy.

## Typed packet values and units

Every selected output property names its physical unit or represents a documented wire enum:

- `F125MotionPlayerData`: header and world X/Y/Z in metres;
- `F125SessionData`: weather, Celsius temperatures, track length in metres, session/track/formula
  enums, spectating/network flags, assist enums, game mode/ruleset, minutes since midnight,
  equal-performance enum, and recovery-mode enum;
- `F125LapPlayerData`: last/current milliseconds, lap/total metres, lap number, pit/sector enums,
  invalid flag, driver status, and result status;
- `F125EventData`: `SessionStarted`, `SessionEnded`, or `Flashback`; Flashback alone carries target
  frame and finite target session seconds;
- `F125CarTelemetryPlayerData`: kilometres per hour, throttle ratio, brake ratio, and signed gear.

Raw byte-backed enums remain numeric in this issue so later audit code can reject unsupported
context explicitly without the decoder inventing semantic defaults.

## Checked field access

The decoder never uses marshaling, unsafe code, native structure layout, host endianness, or a
vendor SDK. `LittleEndianFieldReader` validates every requested offset and width before calling
`BinaryPrimitives`. Player-array absolute offsets use the frozen checked formula:

`header length + (player index × stride) + member offset`.

The exact datagram sizes, strides, member offsets, signedness, and field units are independently
asserted in tests rather than derived from production constants.

## Field-domain validation

The decoder rejects a selected packet when:

- a selected `float32` is NaN or infinity;
- throttle or brake is outside `[0, 1]`;
- gear is outside `[-1, 8]`;
- a documented Boolean is not `0` or `1`;
- a selected bounded enum is outside its published range;
- a Flashback target time is non-finite;
- an Event code contains non-ASCII bytes.

Temperatures, coordinates, lap distance, total distance, and session time may be finite negative
values where the official protocol or game lifecycle can legitimately produce them. No unit
conversion is performed: milliseconds, metres, kilometres per hour, ratios, and Celsius are
preserved exactly.

## Private replay validation

Automated fixtures cannot prove that the owner's existing private base-v3 capture is compatible.
The replay tool therefore adds a narrow `validate-bahrain-decoder` command:

1. parse `--data-root` and `--capture-id` with the same bounded path/ID types as existing replay;
2. open and integrity-check finalized raw evidence;
3. require protocol ID `ea-f1-25-v3`;
4. replay immediately and dispatch only packet IDs 0, 1, 2, 3, and 6;
5. ignore all other compatible families and out-of-slice Event codes;
6. fail on any selected packet rejection;
7. require at least one successfully decoded packet from every selected family;
8. emit a closed, aggregate JSON conclusion containing no counts or evidence values.

The success result contains only schema/status, adapter/contract/decoder IDs, three Boolean gates
(`selectedFamiliesComplete`, `selectedPacketsRejected = false`, `privateDataExcluded = true`), and
`PASS`. Failures expose a bounded categorical status only. The command never serializes capture
IDs, source hashes, paths, sender data, packet counts/rates, frame/session identifiers, field values,
times, coordinates, setup data, or notes.

This command proves decoder compatibility only. Deterministic canonical checksums belong to #26;
manual comparability belongs to #27; the final safe release record belongs to #34.

## Tests

Tests are independently authored from literal byte layouts, not generated from the production
decoder or private telemetry.

### Shared gate tests

- every truncated header and every selected one-byte-short/long packet fails;
- wrong format/year/version/family and invalid player indexes produce exact reasons;
- rejected results contain no typed value;
- fixed-seed arbitrary datagrams never throw;
- the production decoder ID equals the frozen contract ID.

### Family golden fixtures

- Motion verifies all three coordinates, unaligned player selection, finite checks, and 60-byte
  stride;
- Session verifies every selected absolute offset, signed temperatures/track ID, four-byte time of
  day, Boolean and bounded-enum checks;
- Lap Data verifies 57-byte stride, uint32 timing, finite signed distances, and all selected status
  bytes;
- Event verifies all three selected codes, Flashback union offsets, ignored valid codes, non-ASCII
  rejection, and finite Flashback time;
- Car Telemetry verifies uint16 speed, float ratios, signed reverse gear, finite/range checks, and
  60-byte stride.

### Private command tests

- synthetic finalized evidence covers complete, missing-family, selected-rejection, integrity,
  cancellation, and unexpected-failure paths;
- output property sets are exact and recursive privacy-forbidden names are absent;
- private execution is run locally and only its categorical conclusion is referenced by the PR.

## Files and dependency boundaries

- Production packet values and decoder logic stay in `src/ApexLab.Protocols.F125/Decoding/`.
- Checked absolute reads stay internal to `src/ApexLab.Protocols.F125/Parsing/`.
- Unit/golden tests stay in `tests/ApexLab.Protocols.F125.Tests/Decoding/`.
- The private replay command stays in `tools/ApexLab.Replay/BahrainValidation/` with end-to-end tests
  in `tests/ApexLab.IntegrationTests/Replay/`.
- The protocol project continues to depend only on Domain and Telemetry.Abstractions. No UI,
  persistence, database, cloud, or external package dependency is added.

## Explicit non-scope and non-claims

- No complete F1 25 decoder or Season Pack support.
- No setup/status/damage/participants/lobby output and no other-car values.
- No automatic context fingerprint, lap validity, flashback handling, pit inference, resampling, or
  interpolation.
- No persistence schema, canonical cache, UI, detector, experiment, ML, or coaching conclusion.
- No public fixture or output derived from private telemetry.
