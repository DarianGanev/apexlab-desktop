**Status:** Frozen for the provisional `v0.3.0` vertical slice

**Contract ID:** `apexlab-bahrain-tt-slice-v1`

**Machine contract:** [`bahrain-slice-v1.json`](../../contracts/v0.3/bahrain-slice-v1.json)

## Purpose and authority

This document freezes the smallest F1 25 evidence boundary that can support one reproducible,
evidence-linked Bahrain braking experiment. It is the normative human interpretation of the two
machine-readable artifacts above. If prose and JSON disagree, implementation stops until the
contract is deliberately versioned and the disagreement is resolved; downstream code must not
guess.

The wire definitions come from the base-game F1 25 v3 materials registered in
[`protocol-sources.md`](../protocol-sources.md):

| `Data Output from F1 25 v3.pdf` | 659,792 | `850199D1EA817B887B150118095C5CA86527A397D578D53FD5C83427636B92D5` |
| `F1 25 Telemetry Output Structures.txt` | 51,656 | `49CCEADC60A1A6403A59620C6FC09DA377048BA004B15C199399F775B9B3FC69` |

The vendor attachments remain ignored under `vendor-specs/`; they are not redistributed. The
contract contains independently authored field metadata only. Byte positions below assume the
vendor's packed, little-endian layout. An offset identifies the first byte and a width is in bytes.

## Supported evidence boundary

All constraints must hold. A mismatch is unsupported evidence, not a value to coerce or default.

| Property | Required value |
| --- | --- |
| Adapter | `ea-f1-25-v3` |
| Packet format / game year | `2025` / `25` |
| Packet version | `1` for every selected family |
| Track | Sakhir (Bahrain), `trackId = 3` |
| Game mode / session / ruleset | Time Trial: `5` / `18` / `2` |
| Network state | Offline, `networkGame = 0`; internet connectivity is irrelevant |
| Player | Stable `m_playerCarIndex` in `[0, 21]` |
| Secondary player | Absent, `m_secondaryPlayerCarIndex = 255` |
| Spectating | Rejected, `m_isSpectating = 0` |
| Evidence source | One integrity-verified v0.2 raw capture replayed locally |

Only the player entry selected by the validated header is decoded from player arrays. The slice
does not consume other cars, splitscreen, multiplayer, a Season Pack protocol, or a complete packet
catalog.

## Safe output contract

The only v0.3 private-gate result allowed into Git must validate against the closed JSON Schema. It
has exactly 23 required properties: schema/status/date, a bounded path-free game-build label,
application and adapter identity, nine frozen version identities including the contract ID,
three evidence-gate Booleans, baseline-minimum status, categorical finding disposition,
categorical experiment outcome, and final `PASS` or `FAIL`.

A passing result requires the baseline minimum, a finding rather than abstention, deterministic
replay, complete provenance, private-data exclusion, an experiment outcome other than `not_run`,
and `conclusion = PASS`. An abstention forces a failed result, `not_run`, and `FAIL`. Unknown
properties are rejected.

The safe result never contains raw payloads; capture, manifest, session, or frame identifiers;
source hashes; sender information; paths or usernames; exact packet rates; lap or segment times;
coordinates; setup values; or notes. Those values may support local claims but never public proof.

## Failure and abstention

The slice fails closed on an unsupported context, unknown selected packet version, wrong datagram
length, invalid or changing player index, malformed/non-finite required value, broken evidence
integrity, stale derived identity, or incomplete provenance. It abstains from coaching when the
manual audit is incomplete, fewer than five comparable baseline laps remain, material gaps affect
the reviewed region, or detector evidence is weak or contradictory.

`not-followed` is not `rejected`: failure to perform the requested action cannot disprove the
hypothesis. No missing value is replaced with a convenient default.

## Explicit non-claims

- This is one engineering vertical slice over one private, manually audited Bahrain Time Trial
  context—not a generalized track, session, setup, or lap-validity system.
- It does not claim coaching effectiveness, causality, statistical significance, expert
  equivalence, cross-driver validity, or transfer to another car, track, game mode, or game build.
- It does not implement a neural model, chatbot, generative advice, automatic corner discovery,
  automatic validity policy, or complete protocol decoder.
- It does not make real telemetry, derived traces, screenshots, audit values, or vendor attachments
  public.
