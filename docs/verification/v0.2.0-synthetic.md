## Automated coverage

| Risk | Verification |
|---|---|
| Mixed valid, malformed, wrong format/year/ID/version/length, privacy-excluded, and unexpected-sender traffic | `CaptureAdversityTests.FixedSeedMixedCorpusHasExactClassifierAndEvidenceAccounting` runs a shuffled 4,096-datagram fixed-seed corpus. |
| Duplicate payload shapes and reordered classifications | The fixed-seed corpus repeats packet shapes, shuffles their arrival order, and uses non-contiguous source sequences. |
| Source saturation and sequence gaps | `UdpDatagramSourceTests.Saturation_DropsWithoutBlockingAndPreservesSequenceGaps`. |
| Oversized UDP input | `UdpDatagramSourceTests.Source_AcceptsTheConfiguredBoundaryAndRejectsTheSentinelLength`. |
| Port conflict | Probe and desktop workflow integration tests require a typed, privacy-safe bind failure. |
| Slow evidence writer | The adversity corpus yields every compatible write and asserts exact sink accounting; workflow tests cover blocked writes during stop and deferred cleanup. |
| Disk floor, file limit, and duration limit | `RawEvidenceWriterTests` and `CaptureWorkflowTests` cover typed creation/write/finalization outcomes and stop-reason preservation. |
| Corruption | `RawEvidenceReaderTests` rejects data and manifest corruption before returning evidence. |
| Interrupted finalization | Workflow boundary tests prove cleanup starts independently of callbacks, preserves notification order, and exposes terminal failures. |
| Repeated stop/dispose and host shutdown | Workflow and `AppHostLifetimeTests` cover shared ownership tasks, exact-once release, timeout races, and deferred host disposal. |
| Bounded sustained overload | `CaptureSoakTests` drives real loopback UDP through a 256-entry bounded channel and checks managed-memory growth plus source equations. |

The adversity corpus asserts all three accounting boundaries:

```text
observed = enqueued + dropped-full + rejected-oversized
source-dequeued = exactly one classifier outcome per dequeued datagram
compatible = written + write-failed + active-pending + deferred-pending
```

It also finalizes evidence and requires every written record to move from staged to finalized accounting.

## Reproduction

Run bounded CI verification (soak excluded):

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Verify.ps1
```

Run the opt-in loopback soak with its reviewed minimum:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/CaptureSoak.ps1 -DatagramCount 10000
```

The script accepts 10,000 through 5,000,000 requested datagrams. It writes a TRX result and a privacy-safe JSON summary under ignored `artifacts/test-results/capture-soak/`, then prints the JSON summary. The summary contains only the fixed seed, configured rates, elapsed injection and observation times, aggregate counters, and managed-memory measurements.

Local minimum-soak observation on 2026-08-06:

- requested/observed: 10,000 / 10,000;
- source accounting: 10,000 enqueued, 0 full drops, 0 oversized rejects;
- observed managed-memory growth: approximately 6.0 MiB;
- reviewed ceiling: 128 MiB;
- result: PASS.

This observation is a bounded engineering check, not a throughput claim. The required “at least 2x real peak” rate gate cannot be evaluated until the private F1 25 run measures the real peak datagram rate.

After privately measuring the real peak, run a 60-second rate-controlled gate without committing that private value:

```powershell
$realPeak = <privately measured integer datagrams per second>
$minimumObservedRate = [math]::Ceiling(2 * $realPeak)
$targetRate = [math]::Ceiling(1.1 * $minimumObservedRate)
$datagramCount = 60 * $targetRate
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/CaptureSoak.ps1 -DatagramCount $datagramCount -TargetDatagramsPerSecond $targetRate -MinimumObservedDatagramsPerSecond $minimumObservedRate
```

The gate passes only when at least 95% of requested datagrams reach the source, the measured observed rate meets the configured minimum, source accounting remains exact, ordering is preserved, and managed-memory growth stays within 128 MiB. `TargetDatagramsPerSecond` controls the requested injection pace. The observed-rate clock includes bounded receiver drain time, so delayed loopback delivery cannot be credited at the shorter sender-only duration. The JSON records both durations and the achieved send and observed rates. The configured target must not exceed 100,000 datagrams per second and the count must remain within the script bounds.
